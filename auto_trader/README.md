# Automatic Trader v0.2

토스증권 주문 API를 호출하지 않는 `PAPER` 자동매매 시스템입니다. 2단계에서는 토스 현재가를 읽기 전용으로 가져와 PAPER 엔진과 대시보드에 반영할 수 있습니다.

## 실행

```powershell
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python -m auto_trader
```

- API 문서: `http://127.0.0.1:8000/docs`
- 운영 대시보드: `http://127.0.0.1:8000/dashboard`

## 2단계 기능

- 계좌·포지션·주문·전략을 확인하는 대시보드
- `POST /api/v1/market/sync`를 통한 토스 `GET /api/v1/prices` 읽기 전용 연동
- `GET /api/v1/market/related-stocks?keyword=냉각&market=KR` 산업 연관 종목 검색
- 같은 검색창에서 회사명·별칭·티커를 검색하면 개별 종목을 직접 조회합니다. 예: `애플`, `AAPL`, `KB금융`, `105560`
- 섹터·시장·가용현금 투자 비율(10% 단위)을 설정하면 AI 종목·비중 결정과 이동평균 PAPER 전략 실행 자동화
- 5분마다 섹터 후보와 거래대금 순위를 대조해 자동매매 목록 갱신
- 보유 포지션의 종목을 눌러 수집된 틱을 1분 단위 종가 차트로 확인
- 다중 이동평균 전략 등록과 실행
- 일시 정지·재개·긴급 중지 제어

산업 검색은 `auto_trader/related_stock_search.py`의 동의어·기술용어 확장과 회사별 사업·산업·제품·기술 프로필을 이용해 관련도를 계산합니다. 회사명 검색은 종목 별칭 색인을 사용하고, 티커 검색은 토스 종목·시세 API로 이름과 현재가를 확인합니다. 토스의 종목 API는 티커 기반 조회이므로 회사명 별칭 색인은 `DIRECT_STOCKS`에 관리하며, 새 별칭을 추가할 수 있습니다. 토스 조회가 불가능하면 저장된 PAPER 시세가 있는 경우에만 가격을 표시합니다.

냉각 외에 의약·제약·바이오, 우주·위성, 방산, 로봇, 반도체·HBM, AI·클라우드, 전력기기, 원전·SMR, 2차전지·ESS, 신재생·태양광, 조선·LNG선을 검색할 수 있습니다. 추가 종목과 기업 공식 출처는 `auto_trader/sector_catalog.py`에서 관리합니다. 대시보드 섹터 버튼은 검색만 실행하며 기존 자동매매 설정을 변경하지 않습니다. 검색 관련도는 사업 연관성을 나타내며 주가 상승률이나 상승세를 뜻하지 않습니다. 자동 발굴의 거래대금 상위 100종목 필터와 이동평균 매매 조건은 그대로 적용됩니다.

검색 로직 테스트:

```powershell
python -m unittest discover -s tests -p test_related_stock_search.py
```

토스 연동은 `.env`에 Client ID와 Secret을 입력하고 `TOSS_MARKET_DATA_ENABLED=true`로 설정한 경우에만 호출됩니다. 현재 토스 주문 API는 구현하지 않았으며 모든 주문은 PAPER 엔진에서만 체결됩니다.

대시보드의 `섹터 자동 발굴·매매`에서 섹터를 검색하고 가용현금의 투자 비율을 10~100% 중 10% 단위로 선택한 다음 `자동 발굴·매매 시작`을 누릅니다. 종목 수·총 투자금액·주문 수량 입력은 제거했습니다. 서버가 관련 종목(관련도 25점 이상)과 해당 시장 거래대금 상위 100종목을 대조하고, OpenAI가 후보의 사업 연관성·주가·유동성을 바탕으로 종목 수와 신규 투자 비중을 결정합니다. 비중의 합은 100%로 검증하며 AI가 후보 밖의 종목을 추가할 수 없습니다. 사용자가 선택하는 현금 투자 비율과 AI의 종목별 배분 비중은 별개입니다.

예를 들어 시작 시 가용현금이 1,000만 원이고 투자 비율이 30%이면 매수 수수료를 포함한 신규 투자 한도는 300만 원입니다. AI가 두 종목에 60%·40%를 배정하면 신규 투자 한도는 각각 180만 원·120만 원입니다. 여러 종목에 한 번씩 나눠 매수하는 방식이며 시간·횟수 분할 매수는 하지 않습니다. 실제 매수는 기존 이동평균 신호를 따릅니다. 시작 시 확정한 전체 한도를 저장하며 5분 갱신이나 서버 재시작 때 현금 비율을 다시 곱해 추가 투자 한도를 늘리지 않습니다.

AI 자동 배분에는 `.env`의 `OPENAI_API_KEY`가 필요합니다. 모델은 기존 `OPENAI_MODEL`을 사용합니다. 키가 없으면 검색은 가능하지만 새 AI 자동매매 시작은 사용할 수 없으며, 기존에 적용된 자동화는 보존됩니다. AI 계획 API에는 후보 사업정보·현재가·배분용 계좌 수치가 전달됩니다. 키는 브라우저로 전달하지 않습니다. AI 호출 실패·불완전 응답·비중 오류·정지 후 도착한 응답은 새 계획으로 적용하지 않습니다. Responses API의 검증 가능한 구조화 응답을 사용합니다: [OpenAI 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs).

AI 배분 계획은 시작 시와 5분 자동 갱신 시 OpenAI API를 호출하며 API 사용료가 별도로 발생합니다.

`섹터 검색` 버튼이나 입력창의 Enter는 후보 조회만 합니다. 다른 섹터를 검색하거나 입력값을 수정해도 이미 적용된 섹터·선정 종목·투자 배분은 유지되며, 화면의 `적용 섹터`에서 운영 중인 설정을 확인할 수 있습니다. `자동 발굴·매매 시작` 버튼을 직접 눌러야 새 설정을 적용합니다. 5분마다 진행되는 자동 갱신도 마지막으로 적용한 섹터를 기준으로 수행합니다.

신규 현금을 AI 비중대로 나누고 기존 선정 종목 보유·예약 금액을 각 종목 한도에 더합니다. 매수 수량은 `종목의 남은 배분금액 ÷ (예상 체결가 × (1 + 매수 수수료율))`을 1주 단위로 내림합니다. 예상 체결가는 매수 호가(없으면 현재가)에 PAPER 슬리피지를 적용합니다. 매수 신호가 발생할 때 최신 가격·수수료·가용현금으로 재계산하며, 1주를 살 수 없는 잔액은 현금으로 남깁니다. 화면의 예상 수량은 AI 계획 순으로 계산한 예시이며 실제 매수 신호 순서에 따라 달라질 수 있습니다.

기존 보유분의 취득금액·잔여 매수 수수료와 대기 매수 예약금을 전체 한도에 포함합니다. 후보에서 제외되어 매도 대기 중인 종목에 사용한 금액은 새 후보에 중복 배정하지 않습니다. 기존 보유분을 비중에 맞춰 강제 매도하지 않으며 새 매수만 남은 전체 한도와 종목별 한도 안에서 실행합니다. 총 투자금은 누적 거래대금이 아닌 현재 투자 원금과 매수 예약금의 상한이며, 매도 후 남은 한도는 다음 매수에 재사용합니다. 매도 수수료는 매도 대금에서 별도로 차감합니다.

가용현금 비율 배분은 원화 PAPER 장부를 사용하는 국내 주식에 적용합니다. 미국 주식은 검색만 할 수 있습니다. 기존 저장 설정과 API의 `max_symbols`·`total_investment`·`order_quantity`는 이전 설정 복원을 위해 유지합니다. 새 화면은 `cash_percentage`만 전송하고, 이 모드에서는 이전 `max_symbols` 값이 AI 선정 수를 제한하지 않습니다. 기존 설정은 새 시작을 누르기 전까지 자동 변경하지 않습니다.

서버는 5분마다 후보를 다시 선정하고 활성 종목 시세를 15초 간격으로 읽습니다. 기존 고정 이동평균 창(단기 180·장기 460)의 교차를 평가해 PAPER 주문을 실행합니다. 창의 단위는 수집된 시세 표본 수이며, 새 종목은 460개 표본을 확보한 후 첫 관계를 기록하고 이후 교차부터 매매합니다. 15초 간격으로 계속 수집하면 준비에 약 115분이 걸립니다. 시작 버튼이 즉시 매수를 의미하지는 않습니다. 금액 방식은 종목별 금액 한도 안에서 매수하고 매도 신호에는 매도 가능한 보유분 전체를 정리합니다. 수량 방식은 기존처럼 지정 수량과 최대 보유량을 적용합니다.

선정에서 빠진 종목은 보유분이 없으면 목록과 전략에서 제외합니다. 보유분이 있으면 신규 매수를 차단하고 기존 매도 신호를 감시하며, 다음 발굴 때 보유분이 없는 것을 확인한 후 제외합니다. 후보 갱신에 실패하면 기존 선정 목록을 유지하고 화면에 오류를 표시합니다. 정지·긴급 중지 중 도착한 발굴 결과는 적용하지 않습니다. `자동화 정지`는 후보 갱신과 PAPER 매매를 정지하며 보유분을 강제 매도하지 않습니다. `일시 정지` 후 `거래 재개`는 저장된 자동화 설정으로 이어갑니다.

설정과 자동 관리 종목은 로컬 PAPER 상태에 저장되어 서버 재시작 후 복원됩니다. 시세 연동이 설정되지 않으면 자동 시세 수집과 자동매매가 작동하지 않습니다. 섹터 발굴 범위는 현재 등록된 회사 프로필에 한정되며, 전 시장의 산업 정보를 자동 수집하는 기능은 아닙니다. 실제 계좌 주문은 지원하지 않습니다.

자동화 API: `GET /api/v1/auto-discovery`, `POST /api/v1/auto-discovery/start`, `POST /api/v1/auto-discovery/stop`.

대시보드의 `AI 매매 도우미`는 현재 PAPER 계좌·포지션·주문·전략 상태를 읽어 설명하는 읽기 전용 채팅입니다. `.env`에 `OPENAI_API_KEY`를 설정하면 활성화되며, API 키는 브라우저로 전송되지 않습니다. 모델은 `OPENAI_MODEL`로 바꿀 수 있습니다.

## 환경 변수

- `PAPER_INITIAL_CASH`: 가상 시작 자금, 기본 `10000000` (1,000만 원). 주문·보유 내역이 없는 계좌에만 시작 자금 변경을 적용하며, 거래 이후 저장된 잔액은 유지합니다.
- `PAPER_FEE_RATE`: 가상 수수료율, 기본 `0.00015`
- `PAPER_SLIPPAGE_RATE`: 가상 슬리피지율, 기본 `0`
- `TOSS_MARKET_DATA_ENABLED`: 토스 읽기 전용 시세 연동, 기본 `false`
- `TOSS_API_TIMEOUT_SECONDS`: 토스 API 요청 제한 시간, 기본 `10`

## 수동 PAPER 예시

```powershell
$strategy = @{ name = "demo-cross"; symbol = "TEST"; short_window = 2; long_window = 3; order_quantity = "1" } | ConvertTo-Json
Invoke-RestMethod http://127.0.0.1:8000/api/v1/strategies -Method Post -ContentType "application/json" -Body $strategy

$tick = @{ symbol = "TEST"; price = "100"; bid = "99"; ask = "101" } | ConvertTo-Json
Invoke-RestMethod http://127.0.0.1:8000/api/v1/market/ticks -Method Post -ContentType "application/json" -Body $tick
```

실제 계좌와 주문 API는 2단계에서도 비활성화되어 있습니다. 실계좌 전환은 PRD의 PAPER 안정화 기준과 운영자 승인 이후 별도 단계로 진행합니다.
